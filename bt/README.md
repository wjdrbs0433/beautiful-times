# BT — Beautiful Times

Android·iOS용 커플/가족 기록 앱의 첫 개발 버전입니다. Expo + React Native + TypeScript로 구현했습니다.

## 현재 가능한 기능

- 첫 실행 튜토리얼, 커플·가족 공간 전환
- 홈 배경 사진과 기준일 설정(D+1), 일정·앨범·기록 탭
- 일정 생성/수정/삭제, 날짜와 시간 검증, 방문 장소 순서 변경, 구간 이동수단·메모
- 달력으로 기준일·일정 날짜 선택
- 카카오 장소 검색 결과에서 선택, 상단 지도에 큰 방문 번호·화살표 표시
- 키보드 입력 중 지도 접기, 검색 결과 선택 시 키보드 닫기
- 구간별 걷기·자동차·대중교통·자전거 예상 시간 조회 연결(REST API 키 설정 필요)
- 사진 선택·앱 내부 영구 폴더 복사, 원본/고화질 선택, 사진 설명 수정, 기기 사진첩 저장 및 공유 메뉴를 통한 파일 저장
- 글·편지 생성/수정/삭제, 기기 로컬 저장 및 JSON 내보내기
- 계정 연결 상태와 로컬 기록 수·사진 용량 표시

## 실제로 연결되지 않은 기능

카카오 로그인과 같은 계정의 클라우드 동기화를 연결했습니다. 서로 다른 계정의 공동 편집·구성원별 공개·푸시·원격 사용량 확인은 구현/연결 전입니다. 지도는 JavaScript 키와 도메인 등록, 이동시간은 REST API 키 설정이 필요합니다. 지도 연결선은 방문 순서를 나타내며 실제 도로 경로가 아닙니다. 앱은 이 상태를 화면에 표시합니다. 공개 범위 값은 향후 서버 연결을 위한 로컬 메타데이터이며 현재 기기의 다른 사용자로부터 접근을 차단하는 인증 기능이 아닙니다.

사진·배경·일정·글·디데이는 Supabase 계정과 동기화합니다. 서버 보관 완료 전에는 앱 삭제/데이터 초기화 시 유실될 수 있습니다. JSON 내보내기에 사진 파일은 포함되지 않고, 아직 가져오기 UI도 없습니다. 다른 사용자와 공유하는 용도로 배포하기 전에 서버 인증과 권한 검증을 완료해야 합니다.

## 실행

Node.js 24, Java 17, Android Studio/SDK를 사용합니다. Android 네이티브 도구의 최종 요구 버전은 설치한 Expo/RN 빌드에서 확인합니다.

```sh
npm install
npm run android
```

한글 소스 경로의 Kotlin 빌드 오류를 피하기 위해 `npm run android`는 임시 영문 경로에 복사한 뒤 빌드합니다. 소스 원본은 이 폴더에 유지합니다.

이미 개발용 앱을 설치했다면:

```sh
npx expo start --dev-client --localhost
adb reverse tcp:8081 tcp:8081
```

이 개발용 앱은 Mac의 Metro 서버에 연결해 실행합니다. 독립 실행 배포용 APK는 후속 릴리스 빌드 단계입니다. 네이티브 의존성 변경 후에는 개발용 앱을 다시 빌드합니다.

## 지도·이동시간 개발 설정

```sh
npm run routes
adb reverse tcp:8090 tcp:8090
```

Mac에서 http://127.0.0.1:8090/setup 을 열어 JavaScript 키와 REST API 키를 한 번 등록합니다. 비워 둔 칸은 기존 값을 유지합니다. 앱은 10초 이내 또는 일정 화면을 다시 열 때 공개 지도 설정을 자동으로 가져옵니다. 이전 버전에서 저장한 지도 키도 계속 사용할 수 있습니다. 이동시간은 일정 화면의 새로고침으로 다시 조회합니다. 네이티브 앱에서 지도를 사용하려면 WebView가 포함된 최신 개발 빌드가 필요합니다.

키는 Git에서 제외된 `.env.route.local`에 소유자만 읽고 쓸 수 있도록 저장합니다. JavaScript 키는 공개 SDK 식별자이며 앱에서 확인할 수 있습니다. 카카오의 JavaScript SDK 도메인을 필요한 주소로만 제한하세요. REST API 키는 서버만 사용하며 `/public-config`에는 절대 반환하지 않습니다. `EXPO_PUBLIC_`에는 서버 비밀 키를 넣지 마세요.

서버는 loopback에만 바인딩하며 Host/Origin 검사, 설정 폼 CSRF 보호, 1분 60회 조회 제한을 적용합니다. 경로 입력에만 650ms 지연·1분 캐시를 적용하며 메모 입력은 재조회하지 않습니다. 실제 카카오 응답은 키 연결 후 확인해야 합니다.

이 서버는 USB 개발용입니다. 공개 출시 전 HTTPS 서버, 로그인 검증, 공간 구성원별 권한, 사용자별 호출 제한과 총량 제한을 적용해야 합니다. 휴대폰이 Mac과 떨어져도 쓸 수 있는 운영 서버는 아직 없습니다. 사진·글에는 계정별 Supabase RLS와 비공개 저장소를 적용했습니다. 서로 다른 계정의 공간 공유 권한은 추가 구현이 필요합니다.

## Supabase 연결 검사 (2026-11-03)

BT-App Free 프로젝트(서울)가 생성되어 공개 Publishable 키를 `.env.local`에 설정했습니다. DB 비밀번호·secret/service_role 키는 앱에 사용하지 않습니다. 이 파일은 Git에서 제외됩니다.

```sh
npm run check:cloud
```

앱 설정의 **Supabase 연결 테스트**에서도 인증 설정 API와 DB Data API 응답을 확인할 수 있습니다. 빈 프로젝트의 검사 테이블 미존재 응답(PGRST205)은 정상입니다. 이 검사는 실제 테이블 읽기/쓰기, 로그인, 파일 업로드, RLS 정책 검증을 대신하지 않습니다. 기존 로컬 기록은 업로드하지 않습니다.

다음 연결에는 Kakao 공급자 설정, 앱 리다이렉트 주소, 공간·구성원 테이블과 RLS, 비공개 사진 버킷 및 계정별 마이그레이션이 필요합니다. `.env.local` 변경 후 이미 실행 중인 Metro에는 재시작과 앱 새로고침이 필요할 수 있습니다.

## 카카오 가입 테스트

첫 화면에 카카오 로그인 게이트를 적용했습니다. 실제 가입 테스트에는 공급자 키·콜백 및 앱 복귀 주소 설정이 필요합니다. [개발 환경설정 안내](../docs/Windows-개발-시작하기.md)를 참고하고, 실제 프로젝트의 공급자 관리 화면에서 값을 설정하세요. 내부 관리 화면과 계정별 설정 기록은 공개 저장소에 포함하지 않습니다.

로그인 후에는 계정별 기기 저장을 사용합니다. 로그인 이전의 `bt.local.v1` 기록은 그대로 보존하지만 자동으로 계정에 가져오지는 않습니다. 같은 계정의 서버 보관은 연결했습니다. 서로 다른 계정의 공동 공간은 아직 연결 전입니다. 새 네이티브 모듈을 추가했으므로 Android는 개발 빌드 재설치가 필요합니다.

- 일반 앨범 삭제 시 파일 정리·계정 삭제·총 사용량 80% 알림은 후속 작업
- DB에 이미지 바이트·지도 키·로그인 토큰을 넣지 않음

배경 정리 정책: `supabase/migrations/20261109180000_cover_cleanup.sql`. 권한·정리 동작은 `tests/security-database.test.mjs`의 가짜 데이터로 검증할 수 있습니다. 실제 서버 적용·검증은 별도 작업입니다. Storage 메타데이터를 SQL로 지우지 않고 [Storage API](https://supabase.com/docs/guides/storage/management/delete-objects)로 실제 파일을 정리합니다.
